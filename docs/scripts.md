# Scripts

## npm scripts (`package.json`)

| Script | Command | Notes |
|---|---|---|
| `npm run dev` | `next dev` | Local dev server, http://localhost:3000 |
| `npm run build` | `next build` | Production build; also runs the TypeScript type-checker |
| `npm run start` | `next start` | Serves the build from `npm run build` |
| `npm run lint` | `eslint` | Flat config, `next/core-web-vitals` + `next/typescript` |

No `test`, `typecheck`, `format`, `db:migrate`, or `seed` scripts exist. Database migrations and
user data seeding are handled differently — see below — not via npm scripts.

## Database migrations

Not run via an npm script. Apply files under `supabase/migrations/` directly against your Supabase
project, **in filename order**, using the Supabase SQL Editor or `supabase db push` with the CLI
linked to the project. See [`database.md`](database.md) and [`deploy.md`](deploy.md).

There is no migration-generation CLI wired up in this repo — new migrations are hand-written SQL
files named `YYYYMMDDHHMMSS_description.sql`.

## User data seeding

Not a script either — it's application code that runs automatically:

- `src/lib/data/seed-user.ts` (`ensureUserSetup`) runs once per session (memoized in-memory by
  `user_id`) from `SyncProvider` on every authenticated page load. It seeds default categories for a
  brand-new user and runs a couple of idempotent data migrations
  (`migrateOrphanTransactions`, `migrateInvestmentCategories`, `ensureInvestmentCategories`).
- There is no standalone "reset my data" or "re-seed" script — to reset a dev user, delete their
  rows directly in Supabase (categories/accounts/transactions) and reload the app; `ensureUserSetup`
  will reseed categories once it sees the user has none.

## Service worker

`public/sw.js` is a static file, not generated by a build step — edit it directly if you need to
change PWA caching behavior. Registered client-side by
`src/components/pwa/register-sw.tsx`.
